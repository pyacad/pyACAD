The Data panel is for block attributes: the title block fields, equipment tags, room names and door numbers that live inside block references. Take them out to Excel, edit them there and put them back; count blocks into a schedule; or find and replace text across every attribute at once. Every tool here works on the drawing that is open, and its button is greyed until one is.

What it does

Writes one row per block reference to a new .xlsx workbook, on a sheet called Blocks. With block references selected it exports just those; with nothing selected it exports every block reference in model space and on every layout. The workbook is made to be edited and read back by Excel to Blocks, which matches rows to blocks by their handle. The command is PYBLOCKSTOEXCEL.

The columns, in this order:

  • Handle: the reference's handle, which identifies it in this drawing.
  • Block: the block name. A dynamic block reports its definition's real name, not the anonymous *U copy AutoCAD makes.
  • Layer, and Space: Model or the layout's name.
  • X, Y, Z: the insertion point.
  • Rotation in degrees, 0 up to 360.
  • Scale: one number when the X, Y and Z scales are equal, else x, y, z as text.
  • Then one column per attribute tag found on any exported block, in the order the drawing holds them. Tags that differ only in case share a column. A block without that tag has an empty cell.

Rows are sorted by block name, then by handle. The header row is bold.

How to use it

  1. Select the block references to export, or clear the selection to export the whole drawing.
  2. Click Blocks to Excel (or type PYBLOCKSTOEXCEL).
  3. Pick where to save. The suggested name is drawing - Blocks.xlsx beside the drawing (Drawing - Blocks.xlsx for a drawing never saved). Choosing an existing file replaces it.
  4. A toast says how many references were exported, and where.

Good to know / limits

  • Only references placed directly in model space or on a layout are exported. Blocks nested inside other blocks are not.
  • Xref attachments are never included, even when selected.
  • A selection with no block references in it exports nothing, and the toast says to clear the selection to export the whole drawing.
  • If the file is open in Excel, Windows will not let it be replaced: the tool says so. Close it and run again.
  • Constant attributes (fixed in the block definition) are not stored on the reference, so they do not appear. A block with two attributes of the same tag shows only one value.
  • Handles belong to one drawing. The workbook is for reading back into the drawing it came from, or a Save As copy of it.

Other uses

  • A quick register of equipment tags, door numbers or title block fields, without setting up a data extraction.
  • Check positions and rotations at a glance: sort the X column, filter on a layer, look for a scale that is not 1.
  • Hand a list of tagged items to someone who does not have AutoCAD.

What it does

The return trip. It reads the workbook, finds each row's block reference by its Handle, compares the row with the block as it is now, and writes back what you changed: attribute values, and the layer. Before anything changes it says how much will change and asks. The command is PYEXCELTOBLOCKS.

How to use it

  1. Export with Blocks to Excel and edit the workbook: change attribute values, or type another layer name in the Layer column. Save it and close Excel.
  2. With the same drawing open, click Excel to Blocks (or type PYEXCELTOBLOCKS) and pick the workbook.
  3. Read the question, for example Update 12 block references: 30 attribute values, 2 layer changes?, and click Yes.
  4. A toast says how many were updated. If rows were skipped or blocks could not be changed, a dialog lists them, with a Copy button for the full list.
  5. Not what you wanted? U takes the update back.

What goes back, and what does not

  • It reads the sheet called Blocks, or the first sheet when there is no such sheet.
  • Columns are found by their header text, so you may reorder them, hide them, or delete the ones you do not need. Only Handle is required.
  • An attribute column is written to every listed block that has that tag. A changed cell is a change, and an emptied cell clears the value. A tag column the block does not have is ignored: this tool cannot add attributes.
  • A filled-in Layer cell that differs moves the block to that layer. The layer must already exist. An empty Layer cell leaves the block where it is.
  • Block, Space, X, Y, Z, Rotation and Scale are read-only: edits there are ignored.
  • Rows whose handle is no longer a block reference in the drawing are skipped and listed. Rows with no handle are ignored.
  • A block on a locked layer, or moved to a layer that does not exist, is left as it was and listed with the reason; the rest still go in.

Good to know / limits

  • Use a workbook only on the drawing it came from. Handles are numbered per drawing, so a handle from another drawing can belong to an unrelated block here, and that block would be updated if it has the same tags.
  • Excel converts what you type. Type 007 into a General cell and it stores the number 7, which is what comes back. Format a column as Text before typing values with leading zeros, long numbers or anything that looks like a date.
  • When every row already matches the drawing, it says Nothing to update and changes nothing.
  • A file that is not an .xlsx, is damaged, or is locked by Excel is reported, and nothing changes.

Other uses

  • Renumber a set of tags in Excel with a fill-down series, then write them back in one go.
  • Fill in a title block field on every layout from one column.
  • Sort blocks onto the right layers from a spreadsheet: filter by block name, fill the Layer column, run.

What it does

Counts block references and writes the result as a schedule: one row per block name (or per block name and layer), its count, and a Total row at the bottom. The schedule goes either into the drawing as an AutoCAD table or into an Excel workbook. The command is PYBLOCKSCHEDULE.

How to use it

  1. Select the block references to count, or clear the selection to count every one in model space and on every layout.
  2. Click Block Schedule (or type PYBLOCKSCHEDULE).
  3. Choose how to count: Block name, or Block name and layer. The question says how many references it found.
  4. Choose where the schedule goes: Table in the drawing or Excel workbook.
  5. For a table, pick its top left corner. It goes into the current space (model space, or the layout you are on) in the drawing's current table style, with a title row, a header row and columns sized to their text.
  6. For a workbook, pick where to save. The suggested name is drawing - Block Schedule.xlsx, and the sheet is called Schedule.

Good to know / limits

  • The table is a snapshot. It does not update when blocks are added or erased: run the tool again and delete the old table.
  • Rows are sorted by block name, then layer, ignoring case. Dynamic blocks count under their real name, so every variation of one dynamic block is one row.
  • Only references placed directly in model space or on a layout count. Blocks nested inside other blocks do not, and xrefs are never counted.
  • The table's look (fonts, text height, borders) comes from the current table style. Make the style you want current first.
  • If the workbook is open in Excel it cannot be replaced; close it and run again.

Other uses

  • A fixture, equipment or furniture count for one floor: select that floor's area and count just the selection.
  • Count by name and layer to find blocks on the wrong layer: a name that appears on two layers stands out.
  • Check a drawing before issue: the schedule shows stray blocks you did not expect.

What it does

Replaces one piece of text with another inside attribute values, in the block references you choose, in every attribute or only in one tag. AutoCAD's FIND can search attribute text too, but it cannot keep to one tag. The text is plain text, never a pattern, so a * or a . means itself. The command is PYFINDANDREPLACEATTRIBUTES.

How to use it

  1. Optionally select the block references to work on.
  2. Click Find and Replace Attributes.
  3. Type the text to find. Your last search is filled in.
  4. Type what to put instead. Leave it empty to remove the text.
  5. Choose where: Selection (offered when something is selected, with how many objects), Whole drawing, or Pick blocks to select them at the command line now.
  6. Choose which attribute: Every tag, or one tag from the list of tags those blocks carry. The list has a search box.
  7. Choose Ignore case or Match case. Your last choice is offered first.
  8. The changes are made straight away, and a toast says how many values changed in how many block references. U takes them back.

Good to know / limits

  • There is no preview: the replacement happens as soon as you choose the case option. Run Blocks to Excel first if you want to see what is there, and rely on U if the result is wrong.
  • It replaces every occurrence inside a value, not just whole values. Replacing 1 with 2 turns 101 into 202.
  • Blocks on locked layers are left alone, and the toast says how many could not be changed.
  • The find and replace text and the case choice are remembered under %APPDATA%\pyACAD\settings, for every drawing.
  • Only references placed directly in model space or on a layout are searched (or those you select or pick). Xrefs and blocks nested inside other blocks are not.
  • Plain text in the drawing (TEXT, MTEXT) is not touched: only attribute values.

Other uses

  • Change a project number or revision letter in every title block at once, in the one tag that holds it.
  • Rename a room or system prefix across all the tags that carry it.
  • Remove a stray suffix, such as -OLD, by replacing it with nothing.
