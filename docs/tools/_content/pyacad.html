The first panel is pyACAD itself: the things you set once, and the two developer tools that stay useful long after setup. Nothing here touches a drawing. Each button is also an AutoCAD command, so you can type it at the command line or put it in a macro.

What it does

pyACAD keeps its configuration in one JSON file, %APPDATA%\pyACAD\config.json. Most of that file is maintained by pyACAD itself. Settings is the window over the keys a person is meant to change, so nobody has to open the file in a text editor to switch the theme or add an extension folder. The command is PYSETTINGS.

How to use it

  1. Click Settings (or type PYSETTINGS). The window opens with the current values. It is taller than most screens allow, so it scrolls.
  2. Appearance. Theme is Follow AutoCAD (the default), Light or Dark, and sets the colours of pyACAD's own windows, toasts and icons. Two checkboxes control the hints after button captions: a mark after a tool that has a keyboard shortcut (on by default, a filled dot) and a mark after a tool that has a Shift+Click action (off by default, an upward arrow). The box beside each checkbox is the glyph it draws; leave it empty for the default glyph. The checkbox is the only off switch.
  3. Shortcuts. One checkbox, Allow shortcuts without Ctrl or Alt, off by default. Off, every chord must carry Ctrl or Alt. On, a bare letter can be bound, and it then swallows that key everywhere in AutoCAD while the drawing window has focus.
  4. Where extensions are loaded from. Add or remove folders pyACAD scans for *.extension folders. Two locations are scanned whether listed or not: %APPDATA%\pyACAD\extensions, where the installer puts the shipped extension, and %PROGRAMDATA%\pyACAD\extensions when it exists and only administrators can write to it.
  5. Engines. The pyacadlib folder and a CPython executable. Leave both empty to let pyACAD find them. CPython is only used by bundles that declare engine: cpython. A wrong pyacadlib folder stops pyACAD loading at all, so empty is safer than a guess.
  6. AI assistant (beta). The provider, base URL, model, API key (with Test) and longest answer the Ask AI panel uses. The AI Settings page covers this section in full.
  7. Updates. Where this pyACAD stands against the latest release, with Check now, Release page and Skip this version (saved at once, without waiting for Save). Two switches, both on by default: check for a new release once a day, and download it and install it when AutoCAD closes.
  8. Click Save. If an engine path changed, a toast says AutoCAD needs restarting. Otherwise pyACAD asks whether to reload now; Yes rebuilds the ribbon so the changes show straight away, No leaves them for the next Reload.

Good to know / limits

  • Which tool holds which chord is not edited here. That is the Shortcuts editor's job.
  • Engine paths take effect only after AutoCAD restarts. A Reload cannot swap a Python engine under a running ribbon. A *.lib folder added inside an extension folder also needs a restart; a new extension folder needs only a Reload.
  • The window rewrites only the keys it shows. Shortcut overrides and the sizes other dialogs remember stay in the file untouched.
  • Cancel, or closing the window, says nothing and changes nothing.
  • The update check is one anonymous request to GitHub a day. A downloaded installer runs only when its SHA-256 matches the release's, and only after AutoCAD has closed.
  • An update replaces pyACAD.extension whole. Anything you added to or edited inside it is first copied to a dated backup, and buttons and panels you added move to My pyACAD.extension, where they keep their place on the pyACAD tab because tabs and panels with the same names merge on the ribbon. Keep your own tools there from the start.

Other uses

  • Point pyACAD at a shared network folder of extensions so a whole team gets the same tools, and keep your own experiments in a second, local folder.
  • Turn the Shift+Click arrow on while you learn the tab, then off again once you know which tools carry a second action.
  • Copy the version line at the bottom (which pyACAD, for which AutoCAD, and where its runtime lives) into any bug report. pyACAD writes the same line to %APPDATA%\pyACAD\logs\pyACAD.log at every start.

Every key the window writes is described in the authoring guide's config.json reference, which is where to look if you would rather edit the file directly.

What it does

Any pyACAD tool can have a keyboard shortcut and short aliases to type. The shipped tools come with no shortcuts bound, so you choose your own, and with an alias each, like BX for Blocks to Excel, which you can change. This editor lists every tool that can take them, from every loaded extension, grouped by panel and searchable, and lets you set, clear or restore each one. Your choices are stored in config.json under shortcuts.bindings and aliases; a tool's own defaults (its shortcut: and alias: in bundle.yaml) are never touched, so a reset always has something to go back to. The command is PYSHORTCUTS.

How to use it

  1. Click Shortcuts. Type in the search box to narrow the list: it matches the tool's title, its panel's title, its command, and the chord and aliases it has.
  2. Click the field on a row and press the keys you want, for example Ctrl+Shift+B. The field shows the chord and the row reads custom. A chord pyACAD cannot use is refused and the field goes back to what it was.
  3. Backspace in a field clears the binding, and the row reads disabled if the tool had a default of its own. Esc leaves the field as it was.
  4. A chord already held by a tool earlier in ribbon order is flagged under the later row: conflicts with and the other tool's name. Save stays greyed until every conflict is resolved.
  5. Type in the Alias field to change a tool's aliases, for example BX, or BX, B2X for two. Clear it to have none. An alias that another tool holds, that is in your acad.pgp (like CO for COPY), or that AutoCAD already has as a command is flagged in red under the row, and Save stays greyed: your existing keystrokes keep their meaning.
  6. A customised row of a tool that ships its own default has a small reset arrow that puts the default back. Restore All Defaults at the bottom does it for every row at once.
  7. Click Save (enabled once something changed). pyACAD reloads so the new chords and aliases are live straight away, and a toast confirms it.

Good to know / limits

  • A chord always runs the tool's primary action, never its Shift+Click one, and it sends the tool's command exactly as a click does.
  • Chords fire only when the AutoCAD window is in front and the keyboard focus is not in a text box, so typing at the command line or in a palette's filter box is never hijacked.
  • A pyACAD chord wins over an AutoCAD keyboard shortcut on the same keys. Bind Ctrl+Shift+S and Save As is gone from the keyboard until you clear it.
  • Unless Settings allows bare keys, a chord must include Ctrl or Alt.
  • Dock panels (Layer Manager, Ask AI) are not listed: they are reached with their keytip (Alt, then the letters shown on the ribbon).
  • Bindings are keyed by the tool's folder path inside its extension. Moving a tool to another panel drops its override.
  • Saving writes the bindings of the tools that are loaded now. If an extension folder is missing when you save (an unplugged network drive, say), the chords you had given its tools are dropped.

Other uses

  • Give the two or three tools you use daily a chord each, so they are a keypress away without leaving the drawing.
  • Find out whether any extension you installed binds a chord you rely on: search for the chord's letter and read the rows.

What it does

Opens a window where you type Python and run it inside AutoCAD, in the same process and with the same pyacad library the ribbon tools use. It is the fastest way to answer "what does this call return on this drawing" before writing it into a tool, and a handy calculator for one-off jobs that do not deserve a button. The command is PYCONSOLE.

How to use it

  1. Click Console. The window floats beside AutoCAD and AutoCAD stays usable while it is open.
  2. Type in the lower pane and press Ctrl+Enter or click Run. What you ran is echoed with >>> in the upper pane, then its printed output. When the input ends in an expression its value is shown, as at any Python prompt. An error shows its traceback; nothing else is affected.
  3. Up on the first line and Down on the last line walk through what you have run in this window. In the middle of a multi-line input they move the caret as usual.
  4. Names you assign survive between runs, so you can build up an answer a line at a time.
from pyacad import blocks, doc, ents, layers, sel
layers.current()                       # the current layer's name
blocks.counts()                        # {block name: references}
[ents.type_of(h) for h in sel.current()]   # what is selected, by DXF type

Good to know / limits

  • The console runs outside any AutoCAD command, so code that changes the drawing must lock it first: wrap it in with doc.lock():. Reading needs no lock.
  • It is a console, not an editor: there is no file and no save, and history lasts as long as the window. Anything worth keeping belongs in a bundle.
  • Code runs on AutoCAD's UI thread, as every tool does. While it runs, Run reads Running and the window shows the wait cursor; a long loop freezes AutoCAD until it finishes.
  • This is the IronPython 3.4 engine. A bundle that needs numpy runs on CPython and cannot be tried here.
  • Each click opens a new window with its own names and history.
  • print() output lands in the upper pane. Rich output from pyacad.output opens in its own window titled pyACAD - Console.
  • PYACADCONSOLE is a different thing: the loader's diagnostic message box (IronPython version, AutoCAD API version, extensions loaded), there for when the ribbon itself failed to load.

Other uses

  • Count something the interface will not: references per block, entities per layer, the layers matching a pattern.
  • Make a bulk change that does not deserve a tool: with doc.lock(): layers.freeze('A-ANNO-*').
  • Try a helper from the API reference on the open drawing before you build a button around it. The quickstart turns the lines you keep pasting into a button.

What it does

Reads every extension folder again and rebuilds the pyACAD tabs from what it finds. New bundles appear, removed ones go, changed captions, tooltips, icons, keytips and shortcuts take effect, every tool's AutoCAD command is registered again, dock panels are rebuilt, and each extension's startup.py and app-init hook run again. Editing a tool and clicking Reload is the whole development loop. The command is PYRELOAD.

How to use it

  1. Change something on disk: a new bundle folder, an edited bundle.yaml, a new icon, a file in pyacadlib.
  2. Click Reload. A toast says when the ribbon is rebuilt.
  3. Click your button. A script edit alone does not even need this: script.py is read fresh on every run.

Good to know / limits

  • Two things need an AutoCAD restart instead: a changed engine path, and a *.lib folder added or removed (Reload says so in a toast). Edits to files already inside a *.lib folder are picked up.
  • Dock panels are rebuilt from scratch: the Layer Manager forgets its filter text and selection. The Ask AI conversation is kept.
  • Open pyACAD toasts close.
  • Only pyACAD's own tabs are rebuilt. Other add-ins are untouched.
  • If the ribbon is broken badly enough that this button is not there, type PYACADRELOAD: the loader defines it, so it exists even when no extension loaded.

Other uses

  • Pick up an edit to the pyacad library itself: library modules stay cached between runs, and Reload is what refreshes them.
  • Reload writes ==== pyACAD reload ==== to %APPDATA%\pyACAD\logs\pyACAD.log, followed by every bundle it skipped and why, so a button that fails to appear is one log line away from an explanation.
