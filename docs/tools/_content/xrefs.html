Two tools for the drawing's external references. Xref Manager does what the External References palette does one row at a time (reload, unload, detach, bind) to as many xrefs as you tick. Xref Repath rewrites the saved paths of every xref in one pass and shows you each old and new path before it touches anything. Both work on the top-level xrefs only: a nested xref follows the xref that holds it.

What it does

Lists every top-level xref in the drawing, sorted by name, with its status and the path saved in the drawing. You tick the ones to work on, pick one action, and the tool applies it to each xref in turn. One xref that fails does not stop the others: they are all tried, and the ones that did not work are listed at the end with the reason.

Each line of the list reads like this:

Site  [loaded]  ..\Xref\site.dwg
Grid  [not found, overlay]  P:\Jobs\1234\Xref\grid.dwg
Logo  [unloaded]  .\logo.dwg

The word in brackets is the xref's status: loaded, unloaded, not found (the file is not at the saved path or on any search path), unresolved or unreferenced (attached but with no reference left in the drawing). An xref attached as an overlay also says overlay. An xref with no saved path shows (no path).

How to use it

  1. Click Xref Manager, or type PYXREFMANAGER. If the drawing has no xrefs a toast says so and nothing opens.
  2. Tick the xrefs to work on. The search box narrows a long list. Click OK.
  3. Pick what should happen to them: Reload, Unload, Detach or Bind.
  4. For Bind, pick how. Bind keeps each xref's layers and styles apart, renamed in the Site$0$Walls pattern. Insert merges them into the drawing's own layers and styles, the way the INSERT command does.
  5. Detach and Bind ask once more before they start, because both take the xref out of its file's control.
  6. The tool works through the list. When every xref worked, a toast says so (for example "Reloaded 3 xrefs"). When some failed, the toast says how many of how many, and a window lists each failure with its reason. That window shows the first 15; its Copy button puts all of them on the clipboard.

Limitations

  • Nested xrefs are not listed. Reload, unload or bind the xref that holds them.
  • Only a loaded xref can be bound. An unloaded or missing one is reported as not done, with its status as the reason; reload it (or fix its path with Xref Repath) first.
  • AutoCAD reloads an xref whose file it cannot find without raising an error. The tool reads every xref's status again after a Reload, so one that is still not loaded is reported as failed, for example not found at ..\Xref\site.dwg, rather than counted as done.
  • One action per run. To reload some xrefs and unload others, run the tool twice.
  • The tool does not attach or overlay new xrefs. Use XATTACH for that. Images, PDF underlays and other attachments are not listed: only DWG xrefs.

Good to know

A ribbon click sends the PYXREFMANAGER command to the drawing, so the whole run is one command and a single U takes it back, Detach and Bind included. Undo is the only way back from either.

The list is a quick status report in its own right: open it, read it, and press Cancel. Nothing changes until you pick an action.

Other uses

  • Unload the heavy backgrounds before you work on your own layers, and reload them all in one pass before you plot.
  • Reload every xref after a consultant issues new backgrounds, and see at once which ones did not come back.
  • Bind the xrefs into a copy of the drawing for an archive or a transmittal that must open without its reference files.

What it does

Works out a new saved path for each top-level xref in one of four ways, shows you the whole plan, and applies it only when you say yes:

ModeWhat it does to each pathLeft alone when
Make relative Relative to the drawing's folder: .\xref.dwg beside the drawing, ..\Xref\site.dwg from a sibling folder. It is already relative, or it is on another drive or network share.
Make absolute Resolved against the drawing's folder into a full path. It is already absolute.
Find and replace in paths Every occurrence of the text you type is replaced, ignoring case. The text is not in its path.
Point all at a folder The path becomes <folder>\<the xref's file name>. That file is not in the folder, or the xref already points there.

An xref with no saved path is always left alone. After the change, each xref is reloaded from its new path. An xref that was unloaded keeps its new path and stays unloaded until you reload it.

How to use it

  1. Click Xref Repath, or type PYXREFREPATH.
  2. Pick the mode.
  3. Answer what the mode needs. Make relative and Make absolute need nothing more, but the drawing must have been saved: a toast says "Save the drawing first" otherwise. Find and replace asks for the text to find, then the text to put in its place (leave it empty to delete the text). Point all at a folder opens a folder picker, starting in the drawing's folder.
  4. Read the preview. It lists each change as the xref's name with a from line and a to line, then every xref left alone with the reason. It shows 12 of each; Copy puts the full plan on the clipboard. Click OK.
  5. If there is anything to change, confirm Repath ... as shown? If the plan changes nothing, the tool stops after the preview.
  6. A toast reports the result, for example "Repathed 4 xrefs" with "2 left as they were" under it. Failures open a window with the reasons, as in Xref Manager.

Limitations

  • Nested xrefs are never repathed: they follow their parent. Open the parent drawing and repath there.
  • AutoCAD accepts a path it cannot resolve without an error. After the repath the tool reads the statuses again: an xref that was loaded and is not loaded now is reported as failed. In the find and replace and folder modes, which are meant to fix paths, an xref that was missing and is still missing is reported too. The new path stays in place either way; Undo puts the old one back.
  • Make absolute resolves a bare file name such as site.dwg against the drawing's folder, even if AutoCAD had found that file on a support or project path. Check the preview for those.
  • Make relative cannot make a path on another drive or share relative, since there is no relative path between them. Those are listed as left alone.
  • Find and replace works on the whole path, folders and file name alike, so a short search such as A changes more than you meant. Read the preview.

Good to know

The whole repath is one AutoCAD command, so one U undoes every path it changed. Images, PDF underlays and other attachments are not touched: only DWG xrefs.

Other uses

  • The project moved to a new server: find \\oldserver\projects, replace with \\newserver\projects.
  • Make every path relative before you zip the project for a consultant, so the xrefs resolve wherever they unzip it.
  • Swap a whole set of backgrounds for another issue: keep each issue in its own folder with the same file names (Issue B\site.dwg, Issue C\site.dwg) and point all at the new folder. Any file the new folder lacks is reported and left on the old path.
