Toast

The result of a finished action, when the result is one line. A toast is not a dialog: it never asks a question, never carries an action, and never holds anything the user must read to continue. Anything longer than a line belongs in the output window.

Rules

1. The semantic colour rings the whole card. A toast is the one surface that floats free of any chrome, with nothing around it to read the level against, so the colour carries the border as well as the rail. This is the deliberate exception to keeping semantic colour off borders.
2. One line, plus an optional detail line. The detail carries the specific: a path, the first error, the file that was written.
3. Success is silent about the obvious. Toast a result the user cannot otherwise see. Do not toast "Closed" or "Cancelled": closing a dialog is its own feedback.
4. Never print a one-line status instead. A bare print opens the whole output window to show one sentence, which reads as a bug.
5. Duration by weight: success 4s, warning 5s, error 7s. Hover holds it open, clicking dismisses it. At most three stack; the oldest drops.
6. Toasts never outlive their runtime. A reload closes them all, or a topmost window is left orphaned over the host.
