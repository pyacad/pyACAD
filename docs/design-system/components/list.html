The list is always virtualized: only rows on screen may exist as controls, so a document with two hundred thousand items costs the same to show as one with twenty. Folders and other containers live in a rail beside the list, never interleaved as rows.

Rules

1. Virtualize. A list that builds one control per item is a defect, not a slow path.
2. Search first. A search field, live result count, and filter chips sit above the list. Chips filter the view; they never silently change a selection.
3. Standard selection. Click, Shift+click range, Ctrl+click add, Ctrl+A over what is shown, arrows to move, Space to tick. Rows are focusable and show the focus ring.
4. Say what is selected. The strip carries a count plus a breakdown by type, because a bare number hides that one row may stand for a whole folder.
5. Act on the selection. All / None / Invert operate on the visible set, not the document. One primary action per window sits at the right of the strip.
6. Right-click parity. Every context-menu command is reachable another way; a menu is a shortcut, never the only route.
