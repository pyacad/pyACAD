Bulk work: progress and cancel

Anything that edits thousands of things needs three properties: the user can see it moving, the user can stop it, and stopping leaves the document in a state they can describe. A frozen window with no way out is the worst failure mode in the toolkit.

Rules

1. One undo, not thousands. A batch is wrapped in a single document transaction so one Ctrl+Z reverses the whole operation. Ten thousand separate edits will also exhaust the host's undo stack, which silently makes the work irreversible.
2. Count in the label. "Renaming 4,200 of 11,038" tells the user whether to wait or stop. Percentages alone do not.
3. Cancel stops between chunks, then reports what actually finished. Never claim the work was undone if it was not.
4. The API owns the thread. The AutoCAD API is main-thread only, so batches run in chunks with the dispatcher pumped between them. Do not promise background work that cannot exist.
5. Failures do not abort the run. Collect per-item errors, finish the rest, and report the count plus the first message.
6. Show progress only when it earns its place: below a few hundred items the work finishes before the bar renders, and a flash of chrome reads as jank.
